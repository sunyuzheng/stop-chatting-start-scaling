# AI Agent Presentation Playbook

This document captures the reusable logic behind this deck so it can be adapted for future talks at other companies, teams, or communities.

## 1. Core Thesis

The strongest version of the argument is:

- `Chat` improves local tasks.
- `Agents` change the operating model.
- The real difference is not model access or raw intelligence.
- The difference comes from closed loops, richer context, and accumulated assets.
- That is why agentic work can compound while chat workflows hit a ceiling.

This framing is stronger than:

- “AI is getting smarter”
- “Cursor is better than ChatGPT”
- “Prompting is the key skill”
- “Agents are just for engineers”

It works because it shifts the conversation from tool preference to work design.

## 2. Audience Positioning

This presentation pattern works best for:

- large companies exploring AI adoption
- cross-functional operator audiences
- technical and non-technical mixed rooms
- executive or manager audiences who care about leverage, not tool details
- training, keynote, or internal enablement settings

The positioning should change slightly by audience:

- Executives: emphasize operating model, leverage, and talent upgrade
- Managers: emphasize reliability, delegation, and reusable systems
- ICs: emphasize loops, context, assets, and everyday workflow design
- Non-technical operators: emphasize capability expansion, not coding

## 3. Narrative Spine

Use this sequence.

1. Establish the thesis.
2. Show that the performance gap is methodological.
3. Explain why chat workflows cap value.
4. Use one demo story to make the difference concrete.
5. Prove compounding with a second request.
6. Translate the lesson into a maturity model.
7. If relevant, bridge into a course, program, or next step.

This is the durable storyline:

- same models
- different work methods
- different outputs
- different long-term leverage

## 4. Recommended Slide Architecture

Use a structure close to this:

1. Title slide
2. Three claims / talk map
3. Performance gap slide
4. Analogy slide
5. Core contrast divider
6. Why chat is a ceiling
7. Demo setup
8. Starter system / initial state
9. Instruction to the agent
10. Assets created
11. Second request / compounding proof
12. Maturity model
13. Course or program bridge
14. Reviews or evidence
15. Curriculum frame
16. Methods behind the curriculum
17. Closing

## 5. Demo Design Pattern

The demo should not prove that the model is smart. It should prove that the workflow compounds.

Use a task with all of these properties:

- requires context
- requires execution
- requires verification
- spans multiple artifacts or surfaces
- has a natural second-round change

The best pattern is:

- one business change
- across a small but real system
- followed by a second request that becomes cheaper only if structure was created

The most important line is:

- `The second request is the real demo.`

Without that second request, the audience sees speed.
With it, the audience sees compounding.

## 6. Content Principles

### A. Thesis-first, not explanation-first

Every slide should land a point before it explains it.

Prefer:

- “Why the chat window is a ceiling”
- “The first run created assets”
- “The second request is the real demo”

Avoid:

- long explanatory titles
- exploratory wording
- hedging that weakens the claim

### B. One idea per slide

A good slide is usually:

- one sentence thesis
- one contrast
- one list of 2-4 points

If the audience has to read a paragraph to understand the slide, the slide is doing the wrong job.

### C. Use contrasts

This topic becomes much clearer through contrasts:

- chat vs. agent
- open loop vs. closed loop
- disposable answers vs. compounding systems
- local efficiency vs. operating model change
- tool use vs. capability upgrade

### D. Keep course marketing compressed

If there is a course or program CTA:

- keep it to one bridge slide
- use one evidence slide
- avoid a long sales section
- make the curriculum and methods do the persuasion

The strongest CTA is:

- low-pressure
- factual
- evidence-backed
- clearly relevant to the thesis

## 7. The Reusable Maturity Model

This five-stage ladder is the cleanest version:

1. Calibration
   Good judgment about what AI can and cannot do.
2. Usable output
   AI work can enter the workflow directly.
3. Delegation
   Complete tasks move to agentic loops.
4. Memory
   Experience becomes reusable system behavior.
5. Thinking Partner
   AI surfaces better options, tradeoffs, and blind spots.

This is useful because it gives the audience:

- a progression
- a self-diagnosis framework
- a curriculum frame
- a bridge from inspiration to method

## 8. The Reusable Methods Slide

For non-technical or mixed audiences, use this mapping:

- Calibration
  - correct mental models
  - signal / noise filtering
  - real-work capability probing
- Usable Output
  - document-first standards
  - curated context
  - outcome-oriented specs
- Delegation
  - task spectrum mapping
  - comparative advantage focus
  - agentic loops for full tasks
- Memory
  - personal context architecture
  - template and skill library
  - workflow migration, one at a time
- Thinking Partner
  - cross-domain leverage
  - AI-native business design
  - build real projects to expand confidence

This slide works best when it is framed as:

- `These are methods, not prompts.`

## 9. Tone and Wording Rules

Preferred tone:

- crisp
- thesis-driven
- operator-oriented
- confident but not theatrical
- concrete instead of inspirational

Avoid:

- fluffy transformation language
- over-explaining obvious points
- hypey futurism
- too much product evangelism
- too much apology or qualification

Strong wording patterns:

- “The difference is the work method.”
- “The second request is the real demo.”
- “Chat gives advice. Agents work inside the environment.”
- “This is not a tool lesson. It is a capability upgrade path.”

## 10. Visual Design Rules

### A. Business-friendly first

The deck should feel professional before it feels “designed.”

Use:

- restrained typography
- clear hierarchy
- large readable titles
- simple card systems
- one dominant accent color

Avoid:

- multiple competing card colors on one slide
- decorative contrast that does not serve hierarchy
- oversized visual gimmicks
- dense text blocks

### B. One emphasis color per slide

A slide can have:

- neutral cards
- one emphasized card or phrase

It should not have:

- neutral + blue + orange + dark emphasis all competing at once

### C. Layout over novelty

If a layout choice makes one block feel awkward just to preserve symmetry, change the layout.

Prefer:

- clean alignment
- equal card logic
- centered grids when needed
- readable negative space

Over:

- forced asymmetry
- arbitrary spanning cards
- visual tricks that hurt balance

### D. Speaker-friendly density

The slide should act like a memory scaffold, not a document page.

Good slides:

- can be explained in one breath
- can be scanned in three seconds
- give the speaker a clean cue

## 11. Transition Principles

Transitions should feel earned.

Recommended transition logic:

- thesis -> why it matters
- why it matters -> why chat is limited
- limitation -> demo proof
- demo proof -> maturity path
- maturity path -> curriculum
- curriculum -> methods
- methods -> CTA

The audience should feel:

- “I see the argument”
- then “I see the proof”
- then “I see the path”

## 12. Reusable CTA Structure

If closing with a course, community, or offer:

- one slide for the offer
- one slide for evidence
- one slide for curriculum / method credibility
- one closing slide with links

Good CTA components:

- short statement of fit
- one specific offer
- one factual proof point
- one free entry point

For this pattern, the free entry point is:

- `superlinear.academy/c/share-your-projects-en/`

## 13. Pre-Flight QA Checklist

Before sharing externally:

- click through every slide once
- check titles for redundancy or softness
- confirm every slide has one clear point
- verify consistent terminology across the deck
- verify there is no slide with more than one visual emphasis strategy
- check the demo slides still tell a complete story even without a live demo
- check CTA slides feel brief and evidence-based
- check all links and deployed URLs

## 14. What To Reuse Next Time

For a future version, you should be able to reuse:

- the core thesis
- the chat vs. agent contrast
- the “chat window is a ceiling” frame
- the compounding demo structure
- the five-stage maturity model
- the methods slide
- the CTA pattern

What should change by organization:

- opening context
- demo domain
- company-specific examples
- social proof and course offer details
- language around audience pain points
